# Rust dependency audit — 2026-09-05

## Recommendation

Keep the native stack. The useful changes are TLS-provider consolidation, a small Rand migration that removes an entire duplicate RNG generation, and explicit tracking of Linux GTK3 advisory debt. There is no evidence that replacing Reqwest, Tokio, redb, or Tauri would improve Coda enough to justify the migration.

The accompanying [TLS consolidation report](tls-consolidation-2026-09-05.md) records the implemented Ring change, tests, and measurements. Versions below were read from the lockfile during that work. Rand consolidation remains a recommendation.

## Findings worth acting on

### Track the inherited Linux GLib issue separately from maintenance warnings

Locked `glib 0.18.5` falls inside **RUSTSEC-2024-0429**, which identifies unsound iteration in `VariantStrIter`; the published fix is >=0.20.0. No direct use of that iterator was found in Coda source. This establishes affected dependency presence, not a demonstrated exploit or application crash. The dependency comes through the GTK3 desktop stack; adding a direct GLib 0.20 dependency would coexist with, rather than repair, the required 0.18 dependency. Track the Tauri/GTK upstream solution and inspect reachability before accepting a narrow, documented advisory exception. [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2024-0429.html).

The lockfile also matches ten GTK3 binding unmaintained notices, `proc-macro-error`'s unmaintained notice, and five `unic-*` maintenance notices. These are maintenance warnings, not seventeen demonstrated exploitable vulnerabilities. Keep them visible in an eventual official scanner policy; do not blanket-ignore all advisories or force incompatible transitive versions. [GTK3 notice](https://rustsec.org/advisories/RUSTSEC-2024-0415.html), [proc-macro-error notice](https://rustsec.org/advisories/RUSTSEC-2024-0370.html), [UNIC notice](https://rustsec.org/advisories/RUSTSEC-2025-0100.html).

### Consolidate TLS without changing verification policy

Coda's `reqwest/rustls` activates AWS-LC; the updater activates Ring and `reqwest/rustls-no-provider`. Both providers therefore build. Smallest consolidation: use `rustls-no-provider`, directly enable Rustls Ring with default features disabled, and initialize the provider before every client entry path. Keep platform certificate verification, host validation, HTTPS restrictions, and updater signatures intact. Fresh-process tests matter because a previous test can otherwise hide missing initialization.

This changes crypto capability: AWS-LC defaults also advertise hybrid X25519MLKEM768; Ring offers X25519/P256/P384. Do not describe it as identical algorithm support. Compile-time and binary-size savings must be measured after the independent patch. Local evidence: resolved `reqwest-0.13.4/Cargo.toml:86–90,169–176`, `tauri-plugin-updater-2.10.1/Cargo.toml:54–63,104–108`, Rustls provider source, and `cargo tree -e features -i aws-lc-rs` for Windows/macOS. [Reqwest TLS feature documentation](https://docs.rs/reqwest/0.13.4/reqwest/#tls), [Rustls providers](https://docs.rs/rustls/0.23.42/rustls/crypto/index.html).

### Align Coda's Rand with the already-present 0.9 generation

Coda alone introduces `rand 0.8.7`; governor introduces `rand 0.9.5`. Migrating the handful of salt, jitter, and temporary-name calls to 0.9 can remove the old Rand/rand_core/rand_chacha generation. Preserve random Subsonic salts and unpredictability; do not replace randomness with timestamps or deterministic hashes. Verify salt format, collision assumptions, and retry bounds. Jumping directly to current Rand 0.10 would retain governor's 0.9 generation, so latest is not automatically the smallest graph. Upstream documents 0.10 and its breaking changes; supported-version policy is time-bounded. [Rand releases](https://github.com/rust-random/rand/releases), [security maintenance policy](https://github.com/rust-random/rand/security).

### Add a reproducible advisory check before calling the dependency set clean

`cargo audit` was not installed. Repository Dependabot-alert access returned HTTP 403 saying alerts are disabled, so there is no verified working repository alert feed. The audit downloaded the public RustSec database and checked its ranges locally instead; this found the GLib issue and maintenance notices above. Add an official Cargo-audit/deny advisory job with narrowly justified platform exceptions when implementing dependency maintenance. This is an audit recommendation, not a new workflow added here.

## Duplicate graph assessment

The new certificate-rejection regression uses dev-only `rcgen` with defaults
disabled and only Ring enabled. It generates a throwaway certificate and key in
memory instead of storing fixture keys or depending on an installed OpenSSL
command. Its `yasna` dependency is test tooling too; neither is included in
normal release builds. [Certificate generator API](https://docs.rs/rcgen/0.14.7/rcgen/fn.generate_simple_self_signed.html).

Host `cargo tree --duplicates --offline` includes genuine version splits: base64 0.21/0.22, bitflags 1/2, Rand 0.8/0.9, syn 2/3, thiserror 1/2, TOML/winnow generations. Some entries repeat the _same_ version in distinct build/feature contexts; those are not automatically redundant shipped libraries. Most version splits come from Tauri/build tooling and cannot be removed safely with a direct version override. Rand is the clearly owned, small consolidation. Both TLS providers are the clearly owned feature duplication. Do not introduce `[patch]` overrides merely to make the tree look tidy.

## Security evidence and limits

Public RustSec database snapshot `5a0ebed` was downloaded, and 107 records matching locked package names were reviewed through a local range filter followed by inspection of the actionable records. The local helper was not an official Cargo-audit run and does not establish code reachability. Direct locked versions were outside the matching published affected ranges checked. Examples:

- Tauri 2.11.5 is above the 2.11.1 fix for remote-origin IPC confusion on Windows/Android. [Maintainer advisory](https://github.com/tauri-apps/tauri/security/advisories/GHSA-7gmj-67g7-phm9).
- quick-xml 0.41.0 is at the patched boundary for the duplicate-attribute quadratic behavior and associated 2026 parser notice. [RUSTSEC-2026-0194](https://rustsec.org/advisories/RUSTSEC-2026-0194.html), [RUSTSEC-2026-0195](https://rustsec.org/advisories/RUSTSEC-2026-0195.html).
- Rand 0.8.7 and 0.9.5 exceed the applicable patches for the custom-logger unsoundness. [RustSec notice](https://rustsec.org/advisories/RUSTSEC-2026-0097.html).
- tracing-subscriber 0.3.23 exceeds the 0.3.20 patch. [RustSec notice](https://rustsec.org/advisories/RUSTSEC-2025-0055.html).

Full Linux feature-tree generation was unavailable offline because `event-listener 5.4.2` was not cached. Windows/macOS feature trees and the complete lockfile were inspected. There was no Linux runtime test or exhaustive upstream maintenance survey for every transitive crate. No proposed dependency migration has a measured performance improvement yet.

Automatic approval review rejected an OSV batch request because it would send the repository's crate inventory to an external service without destination-specific authorization. No inventory was sent. Downloading public RustSec data and comparing locally supplied the safer alternative; that rejection did not prevent this local review.
