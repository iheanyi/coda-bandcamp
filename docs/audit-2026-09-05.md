## Implemented in this follow-up

- Reuse safe public track projections for unchanged immutable tracks, reducing
  allocation and current-track identity churn on large-queue mutations. The first
  projection has an explicit WeakMap-population cost; see the measured tradeoff.
- Stream Favorites reconciliation results into their bounded output instead of
  retaining every full album until the final response. Stop queued reconciliation
  work when its connection generation becomes stale; preserve partial-failure rules.
- Run warm artwork disk reads and corrupt-entry cleanup on the blocking pool,
  with a regression that proves the async executor can continue while storage waits.
- Avoid allocating/sorting eviction candidates for artwork inserts that already
  fit both cache limits. Preserve replacement, lease and actual-eviction behavior.
- Remove artificial macOS title helpers and four low-value Rust tests: two helper
  mirrors, one duplicate source-string dispatch check, and one numeric parser test
  already covered by real playlist response parsing. No elapsed test-speed claim.

Reproducible measurements and their limits are in the frontend and storage reports.
The Favorites memory improvement is an explicit retained-record model, not RSS.
No native startup, network-speed, or frame-time improvement is claimed.

## Highest-priority remaining work

1. **Player checkpoints still read the whole saved queue every five seconds.**
   Keep authoritative generation/track identity available without rereading up to
   32 MiB, while preserving restart, corruption and failed-write semantics.
2. **Artwork index writes hold the shared runtime mutex.** Offloading reads fixes
   direct filesystem work on async workers, but lock contention can still block
   other operations. Separate durability from runtime ownership carefully.
3. **Artwork revision events notify every mounted cover subscriber.** Measure
   event bursts and scope notifications by cover ID while preserving invalidation.
4. **Cached playlist targets disappear after a background refresh failure.**
   Keep usable targets visible alongside a refresh warning and retry control.

Other findings include malformed Daily HTML rescanning, optional Radio corrections
delaying a usable page, Windows metadata-clear ordering, shutdown disk work,
duplicate-add feedback, and paused checkpoint/feed retention behavior. Their exact
evidence, confidence and next steps are in the detailed reports. These are follow-ups,
not fixes silently claimed as completed.
